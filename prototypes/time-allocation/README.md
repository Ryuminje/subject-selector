# 타임(구획) 배정 프로토타입 — 인수인계 문서

> **상태: 앱에 아직 연결되지 않은 독립 프로토타입입니다.** `src/` 어디에서도 이 폴더를
> 참조하지 않고, 빌드에도 포함되지 않습니다. Next.js 앱으로 이식하기 전의 원본입니다.
>
> 작성: 2026-09-10 / 브랜치 `feature/time-allocation-prototype`

## 1. 이게 뭔가

선택과목 수강신청 결과를 받아 **각 과목의 분반을 어느 타임(구획)에 놓을지 정하고, 학생을
서로 겹치지 않게 각 분반에 배정**하는 프로그램입니다. 학교에서 쓰던 기존 도구의 화면을
사용자가 보여주며 "이런 걸 만들어 달라"고 요청해 처음부터 새로 만들었습니다.

의존성이 하나도 없는 순수 HTML/CSS/JS입니다. 빌드가 필요 없습니다.

```bash
node prototypes/time-allocation/server.js   # http://localhost:3000
```

화면에서 **샘플 불러오기**를 누르면 합성 표본(192명, 가짜 이름)으로 바로 동작을 볼 수 있습니다.

## 2. 이 앱에서 어디에 해당하나

**겹치는 기능이 없습니다.** 수요조사/본조사의 `ClassOpeningStep`은 과목별로 분반을 **몇 개**
열지까지만 정합니다. 그 분반을 **어느 타임에 배치할지**와 **학생을 어느 분반에 넣을지**는
이 앱에 아직 없습니다.

**출력이 기존 입력과 맞물립니다.** 선택과목 변경 탭의 "타임별 시간표 입력"(`change-survey/
components/TimetableStep.tsx`)과 `StudentTimeData { id, name, timeSlotMap }`(`src/types`)가
바로 이 프로그램의 결과물 형태입니다. 지금은 사람이 외부 도구로 만들어 넣는 자료를,
이식하면 앱 안에서 생성할 수 있습니다.

## 3. 핵심 개념 — "타임"과 "구획"

- **타임**: 주간 시간표에서 같은 시수만큼 묶인 시간 덩어리. 선택과목이 3학점이면 타임 1개 = 3시수.
- 학생은 **한 타임에 정확히 하나의 수업**만 듣습니다. 그래서 타임별 인원 합계는 항상 전체 학생 수입니다.
  (이 불변식이 검증의 기준입니다 — 4절 참고.)
- **구획(band)**: 학점 합이 타임 시수를 넘지 않는 공통과목 묶음. 한 타임을 시수로 나눠 씁니다.
  예) 3학점 과목 하나가 구획 1, `2학점 + 1학점`이 구획 2.
- **반 고정 공통과목**: 모든 학생이 듣는 과목. 반(학번에서 뒤 두 자리를 뗀 값) 단위로
  타임이 고정되며, 학생 개인의 선택 여지가 없습니다.

### 교사 수가 타임 구조를 결정합니다

공통과목 교사가 n명이면 한 타임에 최대 n개 반만 들어갈 수 있으므로, `ceil(반 수 / n)`개
타임에 나눠 배치합니다. 8개 반 · 교사 2명이면 4개 타임에 2개 반씩입니다.

**이것이 사용자의 실제 제약이었습니다.** 체육 교사가 2명뿐이라 8개 반이 한 타임에 동시에
체육을 할 수 없었고, 그래서 구획을 여러 타임에 흩는 구조가 나왔습니다. 진로(1학점)는
체육과 같은 구획의 나머지 1시간을 쓰므로 **자기 반에서 100% 수강**이 보장됩니다.

전체 타임 수 = `선택과목 택N` + `구획 수`. 구획을 추가/삭제하면 자동으로 따라갑니다.

## 4. 알고리즘

`public/app.js` 한 파일에 들어 있습니다. 이식할 때 아래 4개는 **화면과 무관한 순수 함수**라
그대로 옮길 수 있습니다.

| 함수 | 하는 일 |
|---|---|
| `parse(text)` | 붙여넣은 TSV를 학기 그룹 / 과목 / 학생 선택으로 분해 |
| `computeFixedBands()` | 구획별로 반을 묶어 타임 고정 (교사 수 제약 + 같은 반 충돌 회피) |
| `runAssign()` | 학생별 이분 매칭 — 선택 8과목을 서로 다른 타임에 배치 |
| `optimize(ms)` | 분반의 타임 위치를 무작위로 바꿔가며 비용 함수를 낮춤 |

- **배정(`runAssign`)**: 학생 한 명당 "선택 과목 ↔ 타임" 이분 매칭(증가경로 DFS)을 돌립니다.
  선택지가 적은 학생부터 처리하고, 각 과목은 인원이 적은 분반을 먼저 시도합니다.
  자기 반 공통과목 타임은 후보에서 제외합니다(`blockedBands`).
- **비용 함수**: `미배정 × 1000 + 정원초과 × 20 + 분반 불균형 × 0.05`. 미배정을 압도적으로
  싫어하도록 가중치를 뒀습니다.
- **초기 배치**: 과목 간 동시 선택 빈도(`coMatrix`)를 이용해 같이 선택되는 과목을 서로 다른
  타임에 놓습니다. 그 뒤 제한 시간(2초) 동안 언덕오르기로 개선합니다.

### 검증 방법 (이식 후에도 이걸로 확인하세요)

**타임별 인원은 반드시 전체 학생 수와 같아야 합니다.** 학생이 한 타임에 한 번만 들어가기
때문입니다. 실제로 이 불변식으로 버그를 하나 잡았습니다(6절).

## 5. 화면 구성

3개 탭입니다. 이식할 때 컴포넌트 3개로 나누면 자연스럽습니다.

1. **데이터 입력** — 엑셀에서 헤더 2줄 + 학생 행을 붙여넣기. 학기 그룹과 `택N`을 첫 헤더
   행에서 자동 인식합니다. 과목은 **열 위치**로 구분하므로 1·2학기에 같은 이름(`심화 영어`)이
   있어도 섞이지 않습니다.
2. **타임 배정** — 메인 그리드. 셀을 클릭해 분반을 수동으로 넣고 뺄 수 있고, 그때마다
   자동 재배정합니다. 공통과목 편집표(과목명/학점/교사 수/구획/삭제)가 위에 붙어 있습니다.
3. **학생별 결과** — 학생 × 타임 표. TSV로 복사해 엑셀에 붙여넣습니다.

## 6. 이미 잡은 버그 (같은 실수 반복 방지)

**진로 인원·반 이중 계산 (2026-09-10 수정).** 진로(1학점)가 체육(2학점)과 같은 구획을
가리키는데, 타임별 집계에서 두 과목을 각각 더해 인원과 반이 부풀려졌습니다.

- 증상: 타임별 인원 합 2,090 (정답 1,900), 반 합 82 (정답 74). 초과분 190이 정확히
  진로 수강생 전체와 일치해 원인을 특정했습니다.
- 수정: 구획의 **첫 과목에서만** 집계하고 나머지는 `shared` 플래그로 건너뜁니다.
- **이식할 때 주의**: 한 구획에 과목이 3개 이상 들어갈 수도 있으므로(1+1+1),
  집계는 반드시 구획 단위로 하세요.

**전사/입력 누락 검증.** 사용자가 처음 붙여넣은 자료에서 열 하나(`과학의 역사와 문화`,
137명)가 통째로 빠져 학생마다 한 타임씩 비었습니다. 지금은 불러올 때 각 학생의
`과목수` 열과 실제 파싱된 선택 수를 비교해 다르면 경고합니다. **이식할 때 이 검증을
빠뜨리지 마세요** — 엑셀 숨겨진 열 때문에 실제로 발생한 문제입니다.

## 7. 함께 들어 있는 분석

`analysis/feasibility.js` — 배정 완료 후 **학기 중 과목 변경이 얼마나 가능한지** 계산합니다.
다른 학생과 분반 배치는 그대로 두고 한 학생만 움직인다는 전제입니다.

```bash
node prototypes/time-allocation/analysis/feasibility.js 31   # 인자는 분반 정원
```

실제 자료(190명, 택8, 17과목, 13,680가지 조합)로 얻은 결과입니다.

| 정원 | 즉시 교체 | 본인 시간표 재배치 | 변경 불가능 |
|---|---|---|---|
| 31명 (실제 최대 분반 인원) | 23.5% | 62.4% | **14.1%** |
| 32명 이상 | 28.4% | 68.0% | **3.6%** |

- **정원 1명 차이가 결정적입니다.** 31→32로 늘리면 불가능 비율이 14.1%에서 3.6%로 떨어집니다.
  분반을 늘리는 것보다 여유석 1~2개를 두는 편이 훨씬 효과가 큽니다.
- **3.6%는 정원을 아무리 늘려도 남는 구조적 한계**입니다(공통과목 타임과의 충돌).
- 바꿔 들어가기 어려운 과목은 분반이 1~2개뿐인 과목입니다(인문학과 윤리 33.5%,
  수학과 문화 29.6%, 도시의 미래 탐구 27.3%). 6분반인 사회문제탐구는 불가능 경우가 0입니다.

**입력 파일 `analysis/assignment.csv`는 이 저장소가 공개라서 커밋하지 않았습니다**
(같은 폴더 `.gitignore`). 로컬 디스크에는 있습니다. 다시 만들려면 앱의
"③ 학생별 결과 → TSV 복사" 결과를 `학번;A타임;…;J타임` 형태(세미콜론 구분)로 저장하세요.

## 8. 이식 계획 (제안)

1. **순수 로직 먼저.** `src/features/time-allocation/lib/domain`(파싱·타입·구획)과
   `lib/scheduling`(매칭·최적화)으로 분리. `exam-scheduler`가 쓰는 폴더 구조와 같습니다.
2. **화면은 새로 작성.** 지금은 문자열로 표를 만들어 `innerHTML`에 넣는 방식이라 그대로는
   못 옮깁니다. 단계별 컴포넌트 + 상태 훅으로 나누고, CSS는 버리고 Tailwind로 맞추세요.
   요소 `id`를 전역으로 쓰므로 그대로 옮기면 기존 화면과 충돌합니다.
3. **탭으로 편입.** `enrollment-helper`의 네 번째 탭을 권합니다(수요조사에서 정한 분반 수를
   이어받을 수 있음). 별도 앱으로 만들려면 `src/config/hub.ts`에 등록.
4. **저장·내보내기.** Prisma로 배정 결과 저장, `exceljs`로 엑셀 내보내기. 둘 다 이미
   이 저장소에 쓰이는 방식이 있습니다.
